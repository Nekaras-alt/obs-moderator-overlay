# Модель угроз — remote connector

[English](../THREAT-MODEL.md)

Область: сопряжение host-приложения с удалённым редактором и опциональная раздача OBS-оверлея через тот же relay (`/o/:code`), чтобы стример мог работать **только с плагином**.

## Активы

- JSON сцены и загруженные медиа на ПК **host** (стример в классике или **модератор** в схеме «только плагин»)
- PIN модератора / viewer token (`data/.secret`)
- Живое управление оверлеем (слои, транспорт медиа)
- Join code (короткоживущий секрет сопряжения; также даёт **просмотр** оверлея через `/o/{code}`)

## Границы доверия

| Сторона | Доверие |
|---------|---------|
| Процесс host у стримера | Полная власть над сценой, если приложение на ПК стримера |
| Процесс host у модератора | Полная власть над сценой в схеме «только плагин» (приложение на ПК мода) |
| Удалённое приложение модератора | После PIN: только правка оверлея — не произвольный доступ к ОС |
| Плагин OBS стримера (Browser remote) | Только просмотр оверлея (join code); без PIN + редактора править нельзя |
| Оператор VPS relay | Видит метаданные шифрованного WSS + байты multiplex-туннеля; **не должен** хранить сцену; honest-but-curious |
| Публичный интернет | Может пытаться угадать join code / DoS против relay |

## Что может модератор

- Открыть UI редактора, проксированный к host `:8090`, после валидного join + PIN
- Менять слои оверлея (как в локальной сессии мода)

## Что может владелец join code (оверлей)

- Открыть `https://relay/o/{code}/obs` (OBS CEF / плагин Browser remote) и видеть живой оверлей + медиа
- Не может открыть редактор или менять слои без PIN

## Чего модератор не может (по задумке)

- Владеть каноническим хранилищем сцены (оно на машине host)
- Добраться до OBS WebSocket (`4455`) или других LAN-сервисов на *другом* ПК (host должен использовать **harden** / bind localhost)
- В схеме «только плагин»: управлять сценами OBS стримера — только оверлей OMO
- Обойти rate limit PIN после поднятия HTTP-туннеля

## Допущения про relay

- Relay — мультиплексор ([`relay/server.js`](../../relay/server.js)): комнаты по join code, TTL, лимит комнат, rate limit по IP, плюс HTTP/WS proxy оверлея `/o/:code` (cookie `omo_room` для абсолютных путей SPA)
- Запросы оверлея используют frame id `ovl-` и не занимают слот редактора `client`
- Нет хранения сцены, нет логов полезной нагрузки
- Компрометация relay ≈ активный MitM туннеля на время пары — смягчается короткими сессиями, доверенным VPS, TLS и ротацией join code (снова **Start relay**)

## Злоупотребления, которые смягчаем

| Злоупотребление | Мера |
|-----------------|------|
| Угадывание join code | Короткие коды + TTL + rate limit на hello/join **и** overlay HTTP |
| DoS медиа оверлея | `OMO_RELAY_OVERLAY_RATE_MAX`, лимит тела, TTL комнаты |
| Два remote-оверлея, один OBS | Cookie `omo_room` с Path=/ — один источник оверлея на OBS |
| Исчерпание комнат relay | `OMO_RELAY_MAX_ROOMS` |
| Повтор устаревшего кода после ухода редактора | Опционально `OMO_RELAY_PAIR_ONCE=1` закрывает слот **editor**; overlay `/o/:code` работает, пока host не уйдёт или не истечёт TTL |
| Случайный публичный 8090 | Harden / `OMO_BIND_LOOPBACK` |
| Ловушки SaaS ToS / лицензий | Self-hosted MIT relay; ngrok/Funnel не как продуктовый default |

## Вне области

- Полное E2E-шифрование внутри mux-кадра сверх TLS до relay
- Модератор только в браузере без remote Electron (отложено)
- Только native-плагин (без sidecar / frame bridge на ПК OBS)
- Защита от злонамеренного модератора, который уже знает PIN
